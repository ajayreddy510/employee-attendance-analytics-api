# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | The grace period check uses `minutes > 10` on floored integer minutes. For punch-in at 09:40:01 with shift 09:30, elapsed time is 10 min 1 sec. `int(601/60)` gives 10, and `10 > 10` evaluates to False, returning 0 instead of 10 (violating R2). Also fails to floor negative differences or truncate instants to whole seconds (R1). | Punch in at `09:40:01` for shift `09:30`. Expected `10`, received `0`. | Truncate instant to whole seconds; check `elapsed_seconds > 600` (strict 10-minute grace); if True, return `int(elapsed_seconds // 60)` from shift start. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's standard `round(..., 2)` which performs banker's rounding (round-half-to-even) on floats rather than arithmetic round-half-up specified in rule R4. | Duration of 9630 seconds (2.675 hours) rounds to `2.67` with banker's rounding instead of `2.68`. | Truncate instants to whole seconds; compute `(punch_out - punch_in).total_seconds() / 3600`, and round using `Decimal` with `ROUND_HALF_UP` quantized to `0.01`. |
| 3 | `compute_overtime` (lines 44-47) | Fails to enforce the 30-minute threshold required by R3 (any positive minutes are returned). For overnight shifts (`shift_end <= shift_start`), `shift_end` is attached to `date_str` rather than the next calendar day, calculating negative or invalid overtime. | A punch-out 15 minutes after shift end returns `15` instead of `0`. Overnight shift (22:00-06:00) punch-out at 06:40 next day gives negative overtime against start day. | Check if shift is overnight and increment calendar day by 1; truncate instants to whole seconds; count whole floor minutes from shift end only if `>= 30`, otherwise return `0`. |
| 4 | `health` (lines 72-74) | Unconditionally returns `{"status": "ok"}` with HTTP 200 without checking MongoDB connectivity. The contract requires returning 200 only if MongoDB answers a ping, otherwise 503. | Terminate MongoDB; request `GET /health`. Returns `200` instead of `503`. | Execute `db.command("ping")` within a timeout try/except block; return HTTP 503 if unreachable. |
| 5 | `create_employee` (lines 77-85) | Race condition: uses check-then-insert (`find_one` then `insert_one`) without a unique database index. Concurrent creates with the same `emp_code` both succeed. | Send parallel `POST /employees` requests with identical `emp_code`; both return 201 Created, generating duplicate employees. | Create a unique index on `employees.emp_code` at startup; catch PyMongo `DuplicateKeyError` and raise HTTP 409 Conflict. |
| 6 | `EmployeeIn` / `create_employee` (lines 53-61, 77-85) | Missing input validations from OpenAPI contract: `emp_code` pattern `^EMP\d{4,6}$`, email pattern, time formats `HH:MM`, valid `joined_on` date, and validation that `shift_start != shift_end`. | POST employee with `shift_start: "09:30"` and `shift_end: "09:30"`, or invalid `emp_code: "foo"`. Server returns 201 instead of 422. | Added strict Pydantic model regexes and validator requiring `shift_start != shift_end` and valid date/time formatting. |
| 7 | `create_employee` (line 82) | Sets `created_at` to naive local datetime (`datetime.now()`) and returns it directly. Schema requires integer epoch milliseconds (`EpochMillis`), and MongoDB stores UTC BSON datetime. | Inspect response of `POST /employees`: `created_at` is an ISO string instead of integer epoch milliseconds. | Store `created_at` in Mongo as UTC datetime (`datetime.now(timezone.utc)`), and return integer epoch milliseconds in response. |
| 8 | `list_employees` (line 93) | Off-by-one pagination error: `skip = page * page_size`. For page 1, `skip = 20`, skipping the first 20 employees entirely. | Call `GET /employees?page=1&page_size=20`; the first 20 employees are missing. | Fixed pagination offset formula to `skip = (page - 1) * page_size`. |
| 9 | `list_employees` (lines 94-95) | Filter ignored in count: `total = db.employees.count_documents({})` counts the entire collection without applying the department filter. Also lacks sorting by `emp_code` ascending. | Filter by department with 2 members out of 50; `total` returns 50 instead of 2. Records are not sorted deterministically. | Count with filter `db.employees.count_documents(q)` and add `.sort("emp_code", 1)` to the MongoDB query. |
| 10 | `punch_in` (lines 100-101, 113) | Missing 404 check for non-existent employee. If `emp` is not found, accessing `emp["shift_start"]` raises an unhandled `TypeError` causing an HTTP 500 error instead of HTTP 404. | Call `POST /attendance/punch-in` with non-existent `emp_code: "EMP9999"`; triggers 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 11 | `punch_in` (lines 104-118) | Concurrency race condition: checks `find_one` then `insert_one` without a compound unique index on `(emp_code, date)`. Two simultaneous punch-ins for the same employee and date both insert. | Send two parallel punch-ins for the same date; both return 201 Created and duplicate records are saved. | Create unique compound index `{"emp_code": 1, "date": 1}` on `attendance_logs`; catch `DuplicateKeyError` and return HTTP 409. |
| 12 | `punch_in` (lines 102-103) | Improper date and timezone calculation: converts timestamp to naive local time and extracts `ts.date().isoformat()`. Attendance date must be IST (UTC+05:30) and handle overnight shifts (R1). | Punch in at 05:00 IST for overnight shift (22:00-06:00) on 2026-07-07; logs date as 2026-07-07 instead of 2026-07-06. | Convert epoch ms to IST timezone; if overnight shift and IST time < `shift_end`, assign date to previous calendar day (R1). |
| 13 | `PunchInIn` / `punch_in` (lines 63-67) | Unchecked status and timestamp bounds: accepts arbitrary status values (ABSENT, LEAVE, or arbitrary text) and seconds-looking timestamps below 100000000000. | Submit `punched_at: 1700000000` or `status: "LEAVE"`; returns 201 Created instead of 422 Unprocessable Entity. | Enforce `PresenceStatus` enum (PRESENT, WFH, ON_DUTY) and `EpochMillis` bounds (`100000000000 <= val <= 4102444800000`). |
| 14 | `punch_in` (lines 119-120) | Exposes internal MongoDB ObjectId via `doc["id"] = str(res.inserted_id)`. The contract states that attendance records have no id field and `_id` must never be exposed. | Inspect `POST /attendance/punch-in` response: contains unexpected `"id"` field. | Do not attach `id` to the document; strip `_id` and return proper `AttendanceRecord` schema with epoch ms timestamps. |
| 15 | `list_attendance` (lines 125-150) | In-memory full collection scan: calls `docs = list(db.attendance_logs.find(q))` and sorts in Python. Fails on ~100k documents. Missing secondary sort `emp_code` asc, missing `date_from > date_to` 422 validation, and injects illegal `"id"`. | Query `GET /attendance` with inverted date filters (`date_from > date_to`); returns 200 instead of 422. With 100k docs, causes severe memory spikes and latency. | Use MongoDB index-backed `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, validate dates returning 422, and serialize BSON datetimes to epoch milliseconds. |
| 16 | Startup & Configuration (lines 22-23) | No indexes are created at startup. The grader expects indexes to be created idempotently at startup so queries and concurrency checks are backed by indexes immediately. | Explain plans on endpoints show `COLLSCAN` and concurrent requests allow race conditions. | Add a startup lifespan handler that creates all required indexes on `employees` and `attendance_logs` idempotently. |

## Items examined and decided NOT to be defects
* **Single-file architecture (`app/main.py`):** While splitting routes and models across modules is standard in larger FastAPI apps, the specification explicitly mandates: *"All application code in this one file `app/main.py`"*. Keeping all models, routes, and helpers in `app/main.py` adheres strictly to the assignment instructions.
* **Storing UTC datetimes in MongoDB while accepting/returning epoch milliseconds:** PyMongo stores datetimes as BSON dates (UTC). Converting epoch milliseconds to UTC BSON datetimes upon write and back to epoch milliseconds upon read is the exact contract requirement defined in `DATA_MODEL.md`.
